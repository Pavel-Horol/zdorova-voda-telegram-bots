Проверь готовность изменений к коммиту.

В проекте НЕТ CI (нет .github/workflows) — эта команда заменяет автоматическую
проверку на push. Выполни строго по порядку и НЕ предлагай коммит, если что-то
красное.

1. `npm run lint` — ESLint с --fix. Если остались ошибки, которые --fix не
   починил, — исправь руками, не игнорируй.
2. `npm test` — все юнит-тесты. Должны быть зелёные. Если упали — почини код или
   тест (разберись, что именно регрессировало), не удаляй и не скипай тест ради
   зелёного прогона.
3. Проверь, что если менялась `schema.prisma` — был выполнен `npm run prisma:generate`.
4. Проверь, что продуктовые изменения отражены в `PRODUCT.md`, а архитектурные
   договорённости — в `CLAUDE.md` (если применимо).

Затем дай краткую сводку:
- что менялось (1–3 строки);
- результат lint и test (числа: сколько тестов прошло);
- предложи текст commit message в conventional-стиле (feat/fix/refactor/docs/test),
  на русском или английском — как в истории репозитория.

Не выполняй git commit сам без явной просьбы — только подготовь и предложи.
