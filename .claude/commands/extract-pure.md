Вынеси чистую логику из бота в тестируемую функцию: $ARGUMENTS

Цель — сделать баго-опасную логику ботов (переходы FSM, парсинг callback,
валидацию ввода, навигацию «Назад») тестируемой БЕЗ живого grammY и БД. Это
безопасный рефактор: поведение НЕ меняется, тесты это доказывают.

Ключевой принцип: **решение отделяем от исполнения.** Async-данные (поход в
сервисы/БД) остаются в хендлере; в чистую функцию передаются УЖЕ загруженные
значения. Не тащи сервисы/ctx/async внутрь чистой функции.

Порядок:
1. Найди логику-кандидата в `client-bot.service.ts` / `dispatcher-bot.service.ts`.
   Хорошие кандидаты: ветвление «Назад» по стеку history; парсинг и валидация
   количества из callback (`Number`, проверки `<1`, `>MAX_ORDER_QTY`); выбор
   per-bottle цены; разбор `editingPriceField` у диспетчера.
2. **Сначала characterization-тест** на ТЕКУЩЕЕ поведение (зафиксируй как есть,
   включая граничные и «защитные» ветки). Прогони — должен быть зелёным на старом коде.
3. Извлеки чистую функцию в отдельный модуль рядом (напр. `client-bot.fsm.ts` или
   `navigation.ts`): вход — примитивы/готовые данные, выход — намерение/значение
   (тип-результат, напр. `{ kind: 'choose-qty' }`), без сайд-эффектов.
4. Замени тело в хендлере вызовом функции + применением её результата. Поведение
   обязано остаться идентичным — тесты из п.2 должны пройти без правок.
5. Вынеси `enum Step` в общий модуль, если функция и сервис оба его используют.

Завершение: `npm run lint && npm test`. Подтверди, что characterization-тесты
прошли без изменений (= поведение сохранено), и перечисли новые тест-кейсы.

НЕ меняй наблюдаемое поведение в этом шаге. Изменения логики — отдельной задачей
поверх уже существующих тестов.
