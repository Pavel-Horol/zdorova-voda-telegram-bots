# DEMO.md — демо-стенд для показа продукта

Демо-стенд — это тот же бот на **отдельных токенах и отдельной БД**, включённый флагом
`DEMO_MODE=true`. Он нужен, чтобы потенциальный покупатель (другой водный бизнес) прошёл
весь путь клиента **сам, без нас рядом**, и заглянул в диспетчерскую часть.

Прод не участвует: у него свой `.env`, свой compose-проект, свой volume и свои токены.

---

## Что меняет `DEMO_MODE=true`

| Поведение | Прод | Демо |
|---|---|---|
| Телефон клиента | просим поделиться контактом | **не просим**: фейковый номер `+38000…` выводится из Telegram-id |
| Обработка заказа | живой диспетчер жмёт кнопки | **авто-диспетчер**: сам принимает (~25 с) и доставляет (~45 с) |
| `/reset` у клиента | нет команды | удаляет данные посетителя, онбординг с нуля |
| Доступ в диспетчерский бот | только разрешённые чаты | **пускает всех** (список диспетчеров правит только супер-админ) |
| Тексты | обычные | баннер «🧪 Демо» на первом экране, после заказа, в `/help` и в профилях обоих ботов |
| Данные | живут вечно | посетители удаляются раз в сутки, цены возвращаются к типовым |
| Витрина | — | при первом старте создаётся фейковая история (3 клиента, 7 заказов) для `/orders`, `/stats`, `🔎 Клієнт` |

Точка входа в код — [`src/config/demo.ts`](src/config/demo.ts) (чистые функции, покрыты
тестами) и [`src/modules/demo/`](src/modules/demo/) (авто-диспетчер, витрина, чистка).
Модуль подключается в `app.module.ts` **только** при включённом флаге — с выключенным
демо-код не инстанцируется вообще.

## Переменные (`.env.demo`)

Шаблон — `.env.demo.example`, сам `.env.demo` в `.gitignore`.

| Переменная | Дефолт | Смысл |
|---|---|---|
| `DEMO_MODE` | — | `true` включает всё описанное выше |
| `DEMO_ACCEPT_DELAY_SEC` | 25 | через сколько «диспетчер» примет заказ |
| `DEMO_DELIVER_DELAY_SEC` | 45 | через сколько после принятия пометит доставленным |
| `DEMO_TTL_HOURS` | 24 | сколько живут данные посетителя (0 = чистить каждый проход) |
| `DEMO_CLEANUP_INTERVAL_MIN` | 60 | как часто крутится чистка |

Мусор и значения вне разумных границ игнорируются — берётся дефолт (таймер на 0 мс
невозможен). Остальные переменные — как обычно: токены, `DISPATCHER_CHAT_ID`,
`SUPPORT_PHONE` (без него не стартует).

**Про две переменные с адресом БД.** `DATABASE_URL` — для процесса на хосте
(`npm run start:demo`, `npm run demo:migrate`), там БД видна как `localhost:5433`.
`DOCKER_DATABASE_URL` — для процесса в контейнере, там хост БД — имя сервиса `db`;
его подставляет `docker/entrypoint.sh`. Так сделано намеренно: подставлять адрес через
`${...}` в compose нельзя — интерполяция берёт значения из `.env` (или из `--env-file`),
а не из `env_file:`, и при запуске «голой» командой молча даёт
`postgresql://:@db:5432` и `P1010: User was denied access`. Пароль в обеих строках
должен совпадать с `POSTGRES_PASSWORD`; спецсимволы — percent-encode (`@` → `%40`).

## Запуск локально

```bash
# 1. Два НОВЫХ бота от @BotFather — демо-клиентский и демо-диспетчерский.
#    ⚠️ Прод-токены не переиспользовать: один токен = один polling-инстанс (409 Conflict).
cp .env.demo.example .env.demo   # вписать токены и свой chat id

# 2. Поднять стенд целиком (бот + БД, миграции накатит entrypoint)
npm run demo:up
npm run demo:logs                # смотреть, что живой

# Остановить / посмотреть / снести вместе с данными
npm run demo:down
npm run demo:wipe
```

Если удобнее гонять код с hot-reload, а в докере держать только БД:

```bash
npm run demo:db          # только Postgres демо (порт 127.0.0.1:5433)
npm run demo:migrate     # миграции на демо-БД (ENV_FILE=.env.demo)
npm run start:demo       # приложение на хосте с .env.demo
```

Проверка после старта: в логах должны быть `DEMO MODE — …`, `DemoModule dependencies
initialized`, `demo showcase seeded` и `demo cleanup every 60 min`.

Сценарий на 2 минуты: `/start` в демо-клиентском боте → онбординг (телефон не
спрашивают) → заказ → в демо-диспетчерском боте появилась карточка → через ~25 с пуш
«прийнято» → через ~45 с «доставлено» → `/reset` → всё сначала.

## Запуск на VPS вторым инстансом

Рядом с продом, в отдельном каталоге:

```bash
git clone <repo> ~/aqua-bot-demo && cd ~/aqua-bot-demo
cp .env.demo.example .env.demo && nano .env.demo     # демо-токены, свой пароль БД
docker compose -f docker-compose.demo.yml up -d --build
```

Изоляция от прода держится на трёх вещах: `name: aqua-demo` в compose (свои контейнеры
и свой volume `aqua-demo_pgdata`), свой `.env.demo` и порт БД 5433 вместо 5432.
Обновление — тот же `up -d --build` после `git pull`. Автовыкатки демо в CI нет
(в `.github/workflows/ci.yml` деплоится только прод) — это осознанно, стенд катится руками.

## Перед передачей стенда покупателю

Профиль обоих ботов (description в пустом чате, «about», список команд) синкается
**из кода при старте** — `syncBotProfile()` в `client-bot.service.ts` и
`dispatcher-bot.service.ts`, тексты в соответствующих `*.texts.ts`. Правки — там,
не в BotFather: ручное значение перетрётся на ближайшем рестарте.

Что BotFather умеет, а Bot API — **нет** (только руками, один раз на бота):

| Шаг | Команда BotFather | Зачем |
|---|---|---|
| Аватарка обоим ботам | `/setuserpic` | пустой кружок с буквой — первое, что видит покупатель |
| Картинка/видео до 15 с над описанием | `/setdescriptionpic` | играет в пустом чате **до** `/start` — показывает флоу раньше любого текста |
| Имя бота | `/setname` | `Здорова Вода — демо` и `Здорова Вода · Диспетчер (демо)` |
| Запретить добавление в группы | `/setjoingroups` → Disable | демо-бота не утащат в чужую группу |

Имя и аватарка **намеренно не в коде**: это идентичность конкретного стенда/клиента
(при white-label меняется на каждого покупателя), а description/about/команды описывают
поведение продукта и обязаны совпадать с кодом.

Чеклист перед отправкой ссылок:

1. Стенд поднят и отвечает: `npm run demo:logs` → `client-bot @… started`,
   `dispatcher-bot @… started`, `demo showcase seeded`.
2. Пройти сценарий на 2 минуты самому (см. выше) — таймеры авто-диспетчера живут в
   памяти, после рестарта запланированные переходы забыты.
3. `/help` в обоих ботах отвечает и содержит демо-приписку.
4. Отправить покупателю **обе** ссылки с пояснением, что вторая — сторона оператора.

## Ограничения (знать заранее)

- **Таймеры авто-диспетчера живут в памяти.** Рестарт процесса забывает
  запланированные переходы: заказ останется в текущем статусе. Очередь ради стенда не
  заводим; если заказ «завис» — его можно принять руками в диспетчерском боте, дальше
  цепочка поедет сама.
- **Посетители видят чужие заказы** в демо-диспетчерском боте — об этом прямо сказано в
  баннере. Телефоны там фейковые, но адреса вводят живые люди: это демо, не храните в
  нём ничего чувствительного.
- **Цены может поменять любой посетитель** — так и задумано (это часть демонстрации),
  чистка вернёт типовые.
- **Витрина создаётся один раз** и не удаляется чисткой (у неё префикс телефона
  `+38001`, у посетителей — `+38000`). Чтобы пересоздать — `npm run demo:wipe` и заново.
