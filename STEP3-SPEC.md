## T1 — Модель: тип заказа + состояние клиента (backbone)

**Зачем.** Заменить грубый `isFirstOrder: boolean` на честный тип заказа и хранить
тару/помпу клиента. Фундамент под онбординг, добор и чужую тару.

**Схема (`prisma/schema.prisma`):**
```
enum OrderKind { STARTER_KIT  OWN_TARA  REPEAT }

model Order {
  ...
  kind  OrderKind   // вместо isFirstOrder
}

model Client {
  ...
  bottlesOnHand Int     @default(0)   // баков в обороте у клиента
  hasPump       Boolean @default(false)
}
```
Миграция: добавить колонки; backfill `kind = isFirstOrder ? STARTER_KIT : REPEAT`;
дропнуть `isFirstOrder`. `bottlesOnHand/hasPump` старым клиентам = дефолты.

**Решение №1 — `bottlesOnHand` обновляется при ДОСТАВКE** (`markDelivered`): клиент
физически получил баки. Хук — существующий переход в `DELIVERED`. STARTER_KIT/добор →
`bottlesOnHand += новые баки`; OWN_TARA → выставляется при заведении (клиент сам ввёл).

**Код:** `pricing.service` (ветки по `kind`, в T1 — 1:1 со старым: STARTER_KIT=комплект,
REPEAT=сетка, без добора/OWN_TARA), `orders.service` (`OrderQuote.kind`, `createOrder`
пишет `kind`), боты (`confirm`/`driverLine`/`orderMessage` по `kind`), все specs.

## T2 — pricing на `kind` + добор тары

**Зачем.** Повторный заказ с учётом баланса тары: лишнее сверх остатка = новая тара.

**Решение №2 — новый бак на доборе = старт-единица** (`залог 450 + старт-вода 50`),
а баки в существующую тару — по сетке.

**Логика (`pricing.service.ts`):**
```
calculateTotal(bottles, kind, prices, bottlesOnHand = 0):
  STARTER_KIT: bottles*deposit + pump + bottles*waterStart      // электро — T5
  OWN_TARA:    waterByGrid(bottles)                             // залог 0
  REPEAT:      newTara = max(0, bottles - bottlesOnHand)
               refill  = bottles - newTara
               waterByGrid(refill) + newTara*(deposit + waterStart)
```
`bottlesOnHand` грузит `orders.service` и передаёт готовым (чистая функция в БД не ходит).
Пример: на руках 2, заказ 3 → `2×70 + (450+50) = 640`.

**Код:** `orders.service` (`quote`/`createOrder`/`editQuantity` подтягивают
`client.bottlesOnHand`); `OrderQuote` — поля для текста добора; `client-bot.texts.confirm`
показывает «+N бак ×(450+50), новая тара» и предупреждение перед Confirm.

**Тесты:** добор-кейсы в `pricing.service.spec`.

## T3 — Онбординг новичка при регистрации + чужая тара

**Зачем.** Как только клиент определён как новый — спросить, что у него уже есть,
и развести по типу заказа. Чинит overcharge действующих клиентов.

**Решение №4 — онбординг на РЕГИСТРАЦИИ**, не на «Заказать воду»: сразу после
«поделиться контактом» (`onContact`), пока клиент «новенький». Если онбординг
прерван и заказа ещё нет — при следующем «Заказать воду» показываем снова
(клиент всё ещё новый: нет заказов, `bottlesOnHand==0 && !hasPump`).

**FSM (`client-bot.fsm.ts` + `client-bot.service.ts`):**
- Новый `Step.Onboarding` + `ScreenIntent { kind: 'onboarding' }`; добавить в
  `ORDER_FLOW_STEPS`, `renderScreen` (switch), `resetSession`.
- `onContact` после регистрации нового клиента → рендер онбординга (вместо сразу меню).
- `resolveStartOrder`: клиент всё ещё новый → `onboarding`; иначе текущая логика.
- Экран «Что у вас уже есть?» (inline):
  - 🆕 Стартовый комплект (бак + помпа + вода) → `kind=STARTER_KIT` → адрес → кол-во → Confirm
  - 💧 Свои баки, нужна вода → `kind=OWN_TARA`: спросить «сколько баков?» (клиент вводит),
    затем «помпа нужна?» → если да, докупка 250 → адрес → Confirm; залог 0, флаг
    «проверить бак при доставке»
  - 🔁 Я уже ваш клиент → T4
  - ⚙️ Другое → T4 (к диспетчеру с возвратом)
- Парсинг выбора и числа баков — чистые функции в `*.fsm.ts` + юнит-тесты (вход недоверенный).

**Решение №3 — у OWN_TARA спрашиваем про помпу** (нет → докупка 250).
**Решение №5 (часть) — число баков вводит сам клиент**; пишем в `bottlesOnHand`/`hasPump`.

## T4 — «Я уже ваш клиент»: подтверждение диспетчером + возврат в бота

**Зачем.** Действующий клиент переходит в бот, не платит залог повторно; бот не
доверяет на слово — диспетчер подтверждает один раз. Любое «к диспетчеру» —
с возвратом в бота, не тупик.

**Решение №5/№6 — клиент сам вводит свои баки/помпу, диспетчер ПОДТВЕРЖДАЕТ.**
Это же и анти-фрод: подтверждение диспетчером + оплата у двери + физическая тара
(мошеннику нечего сдать в обмен) — отдельных мер не вводим.

**Поток:**
- Ветка «🔁 Я уже ваш клиент»: клиент вводит число баков (и есть ли помпа) → создаётся
  заказ `kind=REPEAT` с флагом `Order.needsReview=true` → карточка диспетчеру
  «⚠️ заявлен как действующий — сверить (N баков, помпа …)».
- Диспетчер: кнопка «✅ Подтвердить клиента» → снимает `needsReview`, фиксирует
  `bottlesOnHand/hasPump` со слов клиента (может поправить число).
- **Возврат в бота:** на подтверждение эмитим событие (по образцу `order.status.changed`),
  клиентский бот пишет «Готово, заказывайте в пару тапов». Слушатель fire-and-forget
  (CLAUDE.md прав. 10).
- «⚙️ Другое» — то же: создаём заявку, диспетчер дозаполняет, возврат событием.

**Код:** новое событие в `order-events.ts`; в `dispatcher-bot.service` кнопка
подтверждения; слушатель в `client-bot.service`; `Order.needsReview` в схеме и карточке.

## T5 — Электро-помпа (выбор в комплекте)

**Зачем.** Второй вариант помпы (270) в стартовом комплекте.

**Решение №7 — несколько помп = редкость, на повторном НЕ предлагаем.** Вторая помпа —
только в рамках стартового комплекта/онбординга (или вообще к диспетчеру). На повторном
заказе помпу не докупаем.

**Логика:** электро в комплекте — замена обычной: `STARTER_KIT` с флагом `electro` →
`electroPumpPrice` вместо `pumpPrice` (поля уже в `PriceSettings` с шага 2).
`Order.electro Boolean @default(false)`.

**FSM:** в шаге стартового комплекта — выбор «помпа обычная / электро». Парсинг — чистая
функция + тест.

## Все решения (зафиксировано)
1. `bottlesOnHand` обновляется **при доставке**.
2. Добор = **вода по сетке на всё количество + залог 450** за новый бак (старт-воды на
   доборе нет; пример: на руках 1, заказ 2 → `2×70 + 450 = 590`).
3. OWN_TARA — **спрашиваем про помпу** (нет → докупка 250).
4. Онбординг — **при регистрации** нового клиента (+ повтор, если заказа ещё нет).
5. Число баков **вводит клиент**; для «я уже клиент» — **подтверждение диспетчером**.
6. Анти-фрод — отдельных мер нет, хватает подтверждения + оплаты у двери + тары.
7. Вторая помпа — **не на повторном**, только в комплекте/онбординге.
